# AGENTS.md

Single-module Go library (`github.com/akarshippili/lsm-tree`, Go 1.25). Package name is `lsmtree`, not `lsm` as the README usage snippet suggests. No CI, Makefile, or linter config; `gofmt` and `go vet` are the only checks.

## Commands

```sh
go build ./... && go vet ./... && go test ./...   # full check
go test -run TestSizeTracking -v .               # single test (root package only)
cd test && go run . -log-level debug             # demo binary; MUST run from test/
```

## Layout

- Root package `lsmtree`: `memtable.go`, `sstable.go`, `logger.go`. Tests are `memtable_test.go` and `sstable_test.go` (SSTable tests write to `t.TempDir()`).
- `test/main.go` is a `package main` demo, not a Go test. It writes to `../data/sstable`, so running `go run ./test` from the repo root silently fails (write errors are ignored) and prints an empty result. Run it from inside `test/`.
- `data/` is gitignored; `data/sstable` is a scratch artifact regenerated by the demo. Safe to overwrite.

## SSTable format gotchas (see `sstable.go`)

- No end-of-data sentinel: `Read()` stops at the footer's `indexOffset`, which is where the data section ends.
- Index section is written in data-section order, so it is sorted only if `entries` passed to `NewSSTable` are sorted (`MemTable.Entries()` sorts). `GetIndex()` returns `[]IndexEntry` in on-disk order.
- Index entry offsets are `uint32`, but footer `indexLen`/`indexOffset` are `uint64`. Keep both sides in sync if changing either.
- Sparse index records every 16th entry (`entryIndex % 16 == 0`).
- Deletes store the literal string `__tombstone__` (`Tombstone` const) as the value; `Get` returns it as a normal value.

## Logging

Package-level `defaultLogger` (default level INFO, stdout). Library code calls `defaultLogger.Debug(...)` directly; callers configure it via `lsmtree.SetLogLevel` / `SetLogOutput`. There is no per-instance logger.
